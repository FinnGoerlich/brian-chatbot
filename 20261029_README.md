# Brian

A minimal local chatbot that talks to the Anthropic Claude API through a small FastAPI backend. Its purpose is to prove an API key works end to end.

- Backend: `app.py` (FastAPI + official `anthropic` SDK, streams replies as Server-Sent Events)
- Frontend: `static/index.html` (plain HTML/CSS/JS, served by FastAPI)
- Chats are stored in your browser's localStorage under `brian.chats`

## 1. Setup (once)

Requires Python 3.11 or newer.

macOS / Linux:

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

Windows PowerShell:

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

## 2. Set your API key for this terminal session

Create a key at https://console.anthropic.com → **Settings → API Keys**. Never put the key in a file in this folder; set it only in your terminal session.

macOS / Linux:

```bash
export ANTHROPIC_API_KEY="your-key-here"
```

Windows PowerShell:

```powershell
$env:ANTHROPIC_API_KEY = "your-key-here"
```

The variable only lives as long as that terminal window. Open a new terminal and you need to set it again.

## 3. Run

```bash
uvicorn app:app --host 127.0.0.1 --port 8000
```

Open http://127.0.0.1:8000 and say "Hello".

If the key is missing, the server still starts, logs an error, and the chat shows a clear message. A wrong key shows a "key was rejected (401)" message.

## 4. Change the model

The default model is `claude-sonnet-5-5`. Set `BRIAN_MODEL` before starting the server to use a different one:

```bash
export BRIAN_MODEL="claude-opus-5-5"
```

```powershell
$env:BRIAN_MODEL = "claude-opus-5-5"
```

Brian sends `output_config.effort = "low"` to keep chat replies quick. That works on current Claude models (Sonnet 5.5, Opus 5.5, Haiku 5.5 and others). Very old models that don't support effort will return an error; remove that line in `app.py` if you need one of them.

## 5. Login (optional locally, required when hosted)

Login turns on when both of these are set. Locally you can leave them unset.

| Variable | Meaning |
|---|---|
| `BRIAN_LOGIN_EMAIL` | The email to log in with |
| `BRIAN_LOGIN_PASSWORD` | The password (use a long one on a public site) |
| `BRIAN_SESSION_SECRET` | Random string that signs the login cookie. If unset, a random one is made at startup and everyone is logged out on restart |

After 5 wrong attempts from one address, login is blocked for 15 minutes.

## 6. Hosting on Render

`render.yaml` describes the service. In the Render dashboard choose **New → Blueprint**, connect this GitHub repo, and enter `ANTHROPIC_API_KEY`, `BRIAN_LOGIN_EMAIL` and `BRIAN_LOGIN_PASSWORD` when asked. On Render, Brian stays locked (503) until the login variables are set.

The free plan sleeps after about 15 minutes without traffic; the first visit after that takes up to a minute.

## 7. GitHub Pages version (`docs/`)

`docs/index.html` is a static build of Brian for GitHub Pages. It has no backend: the browser calls the Anthropic API directly with the key you enter at login. The key is kept only in that browser (session only, or on the device if you tick "Remember").

- The email/password check runs in the browser against a SHA-256 hash in the page. It only gates the page; anyone can read the code. The API key is the real lock.
- Your Anthropic organisation must allow browser (CORS) requests. Some organisations turn this off; the login then says so, and you need the server version above.
- The model and settings are constants at the top of the script in `docs/index.html`.

## 8. Brian case-context system (Claude Artifact + Claude Code skill)

Brian collects the context of a closed case that its files don't capture. Everything lives in `.claude/skills/brian/`:

| File | Purpose |
|---|---|
| `SKILL.md` | The `brian` skill for Claude Code: overview, SharePoint folder layout, database layout, rules |
| `review.md` | `/brian review <case code>`: read the case file tree, write `Brian/open_questions.txt`, create or update the case's artifact, load the questions |
| `sync.md` | `/brian sync <case code>`: copy transcripts to `Brian/raw_transcripts/`, uploads to `Brian/files/`, merge unmerged interviews, write `Brian/context.md` |
| `formats.md` | Formats of the questions file, transcripts and `brian.json` |
| `template/brian.html` | The artifact page |
| `template/system_prompt.txt` | Interviewer prompt (gets the case's questions and current context) |
| `template/context_prompt.txt` | How an interview is merged into `context.md` |
| `examples/open_questions_MOCK.txt` | Mock questions for the fictional demo case `DEMO-LIGHTHOUSE` |

### How it fits together

1. Sync the case's SharePoint library with OneDrive and start Claude Code in that folder. Run `/brian review <CODE>`. It writes `Brian/open_questions.txt` and publishes a Brian artifact for the case.
2. Share the artifact with the case team (Contributor). Each member opens it, enters the case code and runs one or more interviews. They can attach PDFs, images and text files. Brian skips what earlier interviews settled.
3. "Finish & update case context" merges the interview into the case's living `context.md`, stored in the artifact's database.
4. `/brian sync <CODE>` copies transcripts, uploads and `context.md` into `Brian/` in the SharePoint, and merges any interview nobody finished.

### The artifact

- No backend and no API key: replies come from the Artifact `sample` capability on the viewer's own Claude account. The interviewer prompt goes in as a leading user turn, because Artifacts have no page-controlled system prompt. Model: `claude-sonnet-5-5`, falling back to the platform default.
- Capabilities: `sample` (with images), `db` and `user` (case data), `assets` (uploads; Contributors may upload), `downloads` (transcript .txt).
- Database: `cases/<CODE>` (questions, context), `cases/<CODE>/chats/<id>` (interviews), `cases/<CODE>/files/<assetId>` (uploads). Interviews are shared with everyone who can open the artifact, which is why each case gets its own artifact.
- Uploads accept PDF, PNG, JPEG, GIF, WebP, .txt, .md, .csv and .json up to 20 MB. Word, Excel, PowerPoint and Outlook files aren't accepted by the artifact's file store. Brian reads text files up to 30,000 characters and images; PDFs are stored for the archive only.

To use the skill from any case folder, copy `.claude/skills/brian` to your personal skills folder (`~/.claude/skills/brian`).
