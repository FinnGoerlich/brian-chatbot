# File formats

## Brian/open_questions.txt

Plain text, UTF-8. The artifact shows Brian this file as written, and Brian reads the `Case:` line for the case name. A full example: [examples/open_questions_MOCK.txt](examples/open_questions_MOCK.txt).

```
OPEN QUESTIONS FOR CASE CONTEXT INTERVIEW
Case code: <CODE>
Case: <project name> - <client>
Case scope (as found in files): <one line>
Case period (as found in files): <YYYY-MM-DD> to <YYYY-MM-DD>
SharePoint folder: <case folder name>
Generated by: Claude Code review of the SharePoint file tree
Generated on: <YYYY-MM-DD>
Files reviewed: <n> (<main types>)

How to read this file: each question has an ID, the question, what the review found, and the files it relates to. Questions are ordered by theme, most important first.

== Theme A: <theme> ==

Q01
Question: <one question, answerable in a few sentences>
Context found: <what the files show, with numbers, dates and document names>
Related files: <path relative to the case folder> ; <path>

Q02
...
```

Rules: IDs are `Q` plus two or more digits, unique and never reused. Paths are relative to the case folder, separated by ` ; `, or `none`.

## Brian/raw_transcripts/<YYYY-MM-DD>_<CODE>_<id8>.txt

The same layout as the artifact's "Save transcript" button, plus the interviewee's name when sync can resolve it. [scripts/write_transcript.py](scripts/write_transcript.py) writes it; use the script rather than formatting by hand.

```
BRIAN CASE CONTEXT INTERVIEW - TRANSCRIPT
Case code: <CODE>
Case: <case name>
Interview: <id8>
Interviewee: <display name, or "Team member">
Interview started: <YYYY-MM-DD HH:MM>
Interview mode: <step by step | all questions at once>
Transcript saved: <YYYY-MM-DD HH:MM>
Messages: <n>
Merged into case context: <yes, on YYYY-MM-DD | no>

Speakers: "Brian" is the AI interviewer; "Interviewee" is the case team member.
The interview closes with a "# Project knowledge record"; settled open questions have a "Recorded for Qnn:" line.

============================================================

[Brian] <YYYY-MM-DD HH:MM>
<message>

[Interviewee] <YYYY-MM-DD HH:MM>
<message>
Attached: <file name> (asset <asset id>)

...
```

Times are local time. Write message text exactly as stored; don't summarize or correct it.

## Brian/context.md

Written by Brian when a debrief is merged and mirrored by `/brian sync`. Never edit it by hand. The full structure and merge rules are in [template/context_prompt.txt](template/context_prompt.txt); in short:

| Section | Holds |
|---|---|
| Case card | Client, industry, functional area, geography, period, case type, summary, key results, good to ask about |
| Project context | Mandate and scope; people interviewed with their role and knowledge boundary |
| Outcomes | What changed, with definition, savings stage, baseline, currency, period and evidence basis; open at handover |
| Procurement know-how | Lessons: situation, action and rationale, reported effect, prerequisites and limits to reuse |
| Key documents | Evidence or reuse purpose, useful component, location or owner, status, sharing needs |
| Open questions | Every question from open_questions.txt with status, answer, who else may know |
| Gaps and follow-up actions | Unknowns, conflicts, agreed next steps |
| Change log | One line per merge or consolidation |

Every statement in Outcomes, Procurement know-how and Key documents names its source: an interview id and/or a file path. Target length: up to about 40,000 characters.

## Case card (`card` in `cases/<CODE>`)

The structured version of the context's case card, shown in Brian Ask and used to match new cases. Brian updates it after each merge ([template/card_prompt.txt](template/card_prompt.txt)); `/brian review` writes the first one from the files.

```json
{
  "client": "Nordwerk Logistics AG",
  "industry": "Logistics",
  "area": "Procurement",
  "geography": "Germany",
  "period": "Mar 2026 – Sep 2026",
  "caseType": "Indirect cost reduction",
  "summary": "2-4 sentences, at most 500 characters.",
  "keyResults": ["up to 3, each with stage and evidence basis"],
  "lessons": ["up to 3"],
  "documents": ["up to 3: document and why it's worth reusing"],
  "goodToAskAbout": ["3 to 6 topics"],
  "completeness": {"settled": 2, "total": 12},
  "updatedAt": 1793294811191
}
```

`area` is the functional area and the first matching criterion; `industry` is shown as the practice area. Brian Ask filters its case cards by both, so keep the names short and consistent across cases ("Procurement", "PMO & value capture", "Pricing", ...; "Logistics", "Chemicals", "Retail", ...).

## SharePoint location (`sharepoint` in `cases/<CODE>`)

Where Brian Ask opens the case's original files, through the asking person's Microsoft 365 connector and with their own SharePoint permissions. Written by `/brian review`.

```json
{
  "driveId": "b!...",
  "folderPath": "Cases/Lighthouse-Nordwerk",
  "name": "Lighthouse-Nordwerk"
}
```

`folderPath` is relative to the drive root, without the document-library segment ("Shared Documents"). A file is opened at `file:///<driveId>/<folderPath>/<path>`, where `<path>` is the path in its digest.

## File digest (`cases/<CODE>/docs/<docId>`)

Written by `/brian review` so Brian Ask can answer from case files when a context isn't enough, and knows where to look in the original. End `text` with a map of the original: slides, worksheets or sections, and what detail is only there.

```json
{
  "path": "04_Analyses/Savings_Baseline_v5.xlsx",
  "title": "Savings baseline v5",
  "type": "xlsx",
  "summary": "One or two sentences.",
  "text": "The digest: what the file is, facts and figures exactly as written, version, reusable part. Up to about 15,000 characters.",
  "modifiedAt": "2026-06-30"
}
```

## Brian/brian.json

```json
{
  "caseCode": "<CODE>",
  "caseName": "<project name> - <client>",
  "artifactUrl": "https://claude.ai/artifact/<id of the Brian library>",
  "createdAt": "<YYYY-MM-DDTHH:MM:SSZ>",
  "lastReview": "<YYYY-MM-DDTHH:MM:SSZ>",
  "lastSync": "<YYYY-MM-DDTHH:MM:SSZ or null>"
}
```
